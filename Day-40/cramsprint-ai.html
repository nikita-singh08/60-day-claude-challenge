How this was built

The brain — system prompt design

The underlying Claude call is given a single strict role: turn a topic or a pile of notes into three things — a short list of key concepts, a multiple-choice quiz, and (implicitly, via per-question explanations) the material needed to compute weak areas after the user answers. It's forced to return only JSON matching a fixed schema, with no preamble, so the frontend never has to guess at formatting.

  • Scope lock: the prompt explicitly refuses to answer anything that isn't "generate a study quiz from this input" — if someone pastes a request to write their essay or asks something off-topic, it returns a JSON error object instead of complying, which the UI shows as a friendly inline error.
  • Missing/thin input: if a topic is too vague ("stuff for exam") or notes are too short to quiz on, the model is told to still produce its best-effort quiz using foundational knowledge of the likely subject, rather than stalling the user.
  • Abuse handling: jailbreak attempts, harmful content requests, or prompt-injection text hidden inside pasted "notes" are explicitly called out as things to ignore — the model treats pasted notes as inert study material, never as instructions.
  • Explanations do double duty: each quiz question carries a short explanation written for the *wrong* answers as much as the right one, so the "weak areas" report at the end can be written in plain language, not just "you got Q3 wrong."

Why the UI looks like this

CS students cramming at 1am don't need a generic chat window — they need something that feels like an exam paper, not a toy. The layout borrows from a marked-up notebook: a coral "spiral binding" edge on the card, a monospace eyebrow label like a stamp, and a highlighter-green accent used only for correctness and progress, so it reads as meaningful signal rather than decoration. The score dial and weak-area cards exist because the one thing a cramming student actually wants at the end isn't a grade — it's a punch list of exactly what to re-read.

Extending this

  • File upload: add a PDF/DOCX drop zone that extracts text client-side (or via a small parsing tool call) and feeds it into the same "notes" input path.
  • Memory across sessions: persist weak-area history (e.g. in window.storage) so returning users get a "last time you were shaky on X" callout before a new quiz starts.
  • Multi-step flow: chain a second Claude call that takes the weak-areas list and generates a focused mini re-quiz on just those concepts, turning this into a spaced-repetition loop instead of a single pass.
  • Tool use: connect a search or textbook-lookup tool so concept explanations can cite the actual course material rather than general knowledge.
